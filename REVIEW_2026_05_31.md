### Cumplimiento de principios POO (UT1)

#### Encapsulación incumplida al cargar datos desde la BD

El repositorio SQLite sigue reconstruyendo `RegistroIncidencia` desde la base de datos asignando directamente atributos protegidos desde fuera de la clase. Los protegidos son protegidos precisamente para que solo la propia clase los modifique, y hay setters con validación que se están saltando con la asignación directa.

Incumplimientos detectados:
- `infrastructure/repositorio_sqlite.py:71-72` (método `obtener`): `inc._estado = fila[2]` y `inc._resolucion = fila[3]`.
- `infrastructure/repositorio_sqlite.py:109-110` (método `listar`): los mismos accesos.

**Cómo arreglarlo**: aceptar los campos persistidos como parámetros opcionales en el constructor:

```python
# En domain/estructura.py
class RegistroIncidencia:
    def __init__(self, id_inc, tecnico, sala, descripcion,
                 estado="Borrador", resolucion="",
                 fecha_apertura=None, fecha_cierre=None):
        # ...validaciones que ya tienes...
        self._estado = estado
        self._resolucion = resolucion
        self._fecha_apertura = fecha_apertura or datetime.now()
        self._fecha_cierre = fecha_cierre
```

Con eso, en `infrastructure/repositorio_sqlite.py` los métodos `obtener` (líneas 69-72) y `listar` (líneas 107-110) construyen el objeto con todos los datos de una vez y nunca tocan `_estado` ni `_resolucion`:

```python
# Sustituir el bloque actual:
#   inc = RegistroIncidencia(id_inc, tecnico, sala, descripcion)
#   inc._estado = fila[2]
#   inc._resolucion = fila[3]
# por:
return RegistroIncidencia(
    id_inc, tecnico, sala, descripcion,
    estado=fila[2], resolucion=fila[3],
    fecha_apertura=fila[4], fecha_cierre=fila[5],
)
```
