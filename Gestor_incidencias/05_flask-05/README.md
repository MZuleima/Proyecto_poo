Gestor de Incidencias Técnicas v5.3.0 — API REST y Transacciones Web SegurasEste proyecto es un sistema de control crítico para la gestión y trazabilidad de incidencias en salas de control. El sistema utiliza una arquitectura por capas (Clean Architecture) para asegurar que la lógica de negocio permanezca independiente de la infraestructura web.En esta fase, la aplicación se ha robustecido con una API REST nativa, gestión de sesiones seguras mediante Flash Messages y una capa de presentación basada en formularios HTTP POST para garantizar la integridad de las transacciones.🛠️ Tecnologías UtilizadasPython 3.8+Flask 3.0.3 (Servidor Web, API REST y enrutamiento)Jinja2 (Motor de plantillas con herencia y persistencia de estado)SQLite3 (Motor de persistencia relacional)Logging (Auditoría centralizada en disco)Unittest (Testing automatizado del núcleo del dominio)🌐 API REST (Interfaz JSON)El sistema expone una interfaz programática para la consulta de datos, ideal para integraciones externas.EndpointMétodoDescripción/api/incidenciasGETObtiene el listado completo de incidencias en formato JSON./api/incidencias/<id>GETObtiene el detalle técnico de una incidencia específica.Ejemplo de consumo (cURL):Bashcurl -X GET http://127.0.0.1:5000/api/incidencias
🚀 Requisitos e InstalaciónPara desplegar la aplicación:Instalar dependencias:Bashpip install -r requirements.txt
Inicializar la base de datos:Bashpython crear_bd.py
Ejecutar el servidor:Bashpython -m presentation.app
El servidor estará disponible en: http://127.0.0.1:5000/🎨 Mecanismos de Robustez WebPatrón Post/Redirect/Get (PRG): Todas las operaciones de mutación (crear/resolver) finalizan con una redirección para evitar duplicados al refrescar el navegador (F5).Flash Messages: Sistema de notificaciones transitorias (éxito/error) que mejoran la experiencia de usuario (UX) tras completar formularios.Persistencia de Formularios: Si el dominio rechaza una operación, el formulario se re-renderiza manteniendo los datos introducidos por el usuario, evitando pérdida de información.Seguridad: Uso de app.secret_key para la firma segura de cookies de sesión necesarias para las alertas flash.🛣️ Mapeo de Rutas (Verbos HTTP)⚙️ Lectura y Diagnóstico (GET)/: Inicio./incidencias: Listado HTML./tecnicos / /salas: Catálogos maestros./ayuda: Mapa de rutas del servidor./provocar-error: Endpoint de test para errores 500.📝 Escritura (GET/POST)/incidencias/nueva: Registro de nuevas incidencias./incidencias/<id>/resolver: Cierre técnico de reportes.🚫 Acciones Puramente POST (Seguridad de Estado)/incidencias/<id>/documento: Emisión de acta técnica.📂 Documentación AdicionalEl desglose técnico detallado se encuentra en la carpeta docs/:docs/EJECUCION.md: Guía de despliegue y matriz de verbos.docs/ARQUITECTURA_POR_CAPAS.md: Diagrama de flujo de dependencias.docs/CONTRATO_REPOSITORIO.md: Gestión del almacenamiento SQLite.Gestor de Incidencias v5.3.0 - Arquitectura de Capas Limpia
