El sistema soporta un doble entorno de presentación (interfaz de línea de comandos clásica y servidor API Web mediante Flask) conectados al mismo motor de persistencia relacional SQLite. Esta versión elimina el paso de parámetros de escritura por URL (`GET`), implementando **formularios estructurados HTTP POST**, validación con re-renderizado persistente y el patrón **PRG (Post/Redirect/Get)**.

Mecanismos de Robustez de la Interfaz Web🛡️ 1. Patrón Post/Redirect/Get (PRG)Cuando registras una nueva incidencia o firmas la resolución de un reporte y haces clic en enviar, los datos viajan de manera segura ocultos en el cuerpo del POST. Al completarse la transacción con éxito en SQLite, el controlador ejecuta un return redirect(url_for('listar_incidencias')). Esto fuerza al navegador a realizar una petición de lectura limpia (GET). Si el usuario refresca la pantalla con F5, la acción no se duplica ni se reenvían los datos del formulario.🔄 2. Re-renderizado con Persistencia de DatosSi se intenta registrar una incidencia utilizando un ID numérico que ya está asignado en la base de datos, el dominio relacional rechazará la operación lanzando un error de conflicto. El servidor interceptará la excepción, devolverá un estado 409 Conflict o 400 Bad Request, y volverá a pintar el formulario mostrando un cartel informativo de alerta. Los campos de texto y selectores que el usuario ya había rellenado se conservarán intactos, evitando tener que escribir toda la descripción del fallo técnico de nuevo.🚫 3. Protección de Canales SecundariosSi se intenta introducir directamente en la barra de direcciones del navegador la URL de generación de actas (ej. http://127.0.0.1:5000/incidencias/1/documento), el servidor Flask interceptará la petición rechazándola al instante con un código de estado estándar 405 Method Not Allowed, asegurando que ningún estado varíe accidentalmente por indexaciones automáticas o precargas.4.
